An AI agent for private-credit data. It extracts every holding from the schedule-of-investments tables BDCs file with the SEC, checks each number against the filing's own XBRL tags, and answers analyst questions with a verified citation for every figure.

{{NOTE_BLOCK}}

How it works

1. ExtractParses messy EDGAR tables (split pages, "$" cells, footnotes, carried-down names) into one clean row per holding.
2. Cross-checkReconciles every row, the coverage and the totals against the filing's inline XBRL. Two independent sources must agree.
3. AnalyzeDerives spreads, marks, non-accruals and PIK, then tracks changes by quarter and compares lenders.
4. AnswerAn agent with read-only tools answers questions; a citation only counts if the agent actually retrieved that row.

Early warnings: marks that may be stale

Private credit loans don't trade, so a loan can sit near full value and then be cut to a fraction a quarter later. These are the patterns that come before those surprises: lenders that disagree sharply on the same borrower, and loans that fell from near full value in a single quarter.

Why you can trust the numbers

Every real filing is reconciled against its own XBRL tags; a sample was hand-checked field by field. Synthetic filings with exact answer keys stress unusual layouts in the test suite.

Design choices

  • Two independent sources: parsed tables are reconciled with inline XBRL. Missed rows, wrong column mappings and unit mistakes show up without any answer key.
  • Grounded by construction: the model never sees raw filings; it queries a read-only database through narrow tools.
  • Citations are verified, not trusted: a cited row the agent never retrieved counts as unsupported.
  • No per-filer code: one extractor handles every layout in the stress-test suite (reordered columns, split headers, <th> headers, footnotes, millions vs thousands).
  • Traceable: every holding keeps its table, row, original text and XBRL context.
